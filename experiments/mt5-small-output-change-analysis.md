# mT5-small 要約出力の変化分析

実行日: 2026-06-07

## 目的

`google/mt5-small` を用いた要約実験について、数値指標だけでなく、Baseline / Proposed、Full fine-tuning / LoRA fine-tuning の違いによって生成要約が具体的にどう変化したかを確認する。

生成された要約文そのものの具体例は `experiments/mt5-small-generated-summary-examples.md` に掲載する。

比較対象:

- Full FT + Baseline
- Full FT + Proposed
- LoRA FT + Baseline
- LoRA FT + Proposed

評価対象は test 3 件である。データ数が少ないため、ここでの分析は定性的な傾向確認であり、一般化できる結論ではない。

## 全体傾向

| 条件 | char ROUGE-L | 出力傾向 |
| --- | ---: | --- |
| Full FT + Baseline | 0.0648 | 長い反復が多い。敬語・定型句に崩れやすい。 |
| Full FT + Proposed | 0.0303 | Baseline より短くなるが、`act` / `stance` など入力ラベルが出力に漏れる。 |
| LoRA FT + Baseline | 0.1043 | 4 条件中で最高スコア。ただし反復は残り、実用的な要約には届かない。 |
| LoRA FT + Proposed | 0.0577 | Full Proposed より改善。短く、入力中の質問断片を拾う例があるが、要約としての被覆は低い。 |

全条件で `<extra_id_0>` が先頭に出ている。これは T5 / mT5 系の sentinel token が生成に残っている状態であり、後処理または生成設定の改善が必要である。

## サンプル別分析

### test_001: 非核三原則をめぐる党首討論

参照要約の主題:

- 高市早苗首相と野党党首による党首討論
- 公明党の斉藤鉄夫代表が非核三原則の見直しを質問
- 高市首相が「政策上の方針としては堅持」と答弁

生成の変化:

| 条件 | 生成の特徴 |
| --- | --- |
| Full FT + Baseline | 「よろしくお願いいたします」を長く反復。主題である非核三原則・党首討論・高市首相は出ない。 |
| Full FT + Proposed | 同じく「よろしくお願いいたします」を長く反復。句点は増えるが、内容改善はほぼない。 |
| LoRA FT + Baseline | 「国民の国民の...」を反復。政治文脈らしい語は出るが、主題は復元できない。 |
| LoRA FT + Proposed | 「いたします。」だけの極端に短い出力。反復は減ったが、情報量も失われた。 |

解釈:

test_001 では、いずれの条件も要約として失敗している。Proposed 入力や LoRA によって反復の種類や長さは変わったが、参照要約の主要事実は生成されていない。

### test_002: 山添拓議員と小泉防衛相、非核三原則

参照要約の主題:

- 参議院外交防衛委員会
- 共産党の山添拓議員が小泉進次郎防衛相の答弁姿勢を批判
- 非核三原則の位置付けをめぐる質疑
- 茂木外相が「政策上の方針として堅持」と答弁

生成の変化:

| 条件 | 生成の特徴 |
| --- | --- |
| Full FT + Baseline | 「ことでございます」を反復。内容語はほとんどない。 |
| Full FT + Proposed | 「山沢拓君」という人名らしき語が出る。山添拓に近いが誤字で、要約にはならない。 |
| LoRA FT + Baseline | 「そして、そのことについて述べました」を反復。ROUGE-L は最も高いが、汎用文の反復による偶然の文字一致が大きい。 |
| LoRA FT + Proposed | 「しました。」のみ。反復はないが情報量がほぼない。 |

解釈:

test_002 では、LoRA Baseline の ROUGE-L が高いが、実際の出力は「そのことについて述べました」の反復であり、内容把握ができているとは言いにくい。Full Proposed は人名らしき断片を拾うが、`山添拓` を正しく出せず、主題の非核三原則や防衛相答弁には到達していない。

### test_003: 現金給付報道、減税、党首討論

参照要約の主題:

- 石破茂首相と野党党首による党首討論
- 国民民主党の玉木雄一郎代表が現金給付報道を批判
- 「バラマキではなく減税こそが筋」と主張
- 石破首相が政府内検討を否定し、困窮者支援を説明

生成の変化:

| 条件 | 生成の特徴 |
| --- | --- |
| Full FT + Baseline | 「誠に」を大量反復。要約内容は出ない。 |
| Full FT + Proposed | `[委員長] act: question | stance: negative | text:` が出力に漏れる。Proposed 入力のラベル形式を生成してしまっている。 |
| LoRA FT + Baseline | 「玉木雄一郎さんありがとうございます」を反復。参照要約の人物名は拾えているが、論点は出ない。 |
| LoRA FT + Proposed | 「現金配るんですか」「石破茂さん、挙手をお願いします」という質問断片を出す。4 条件の中では最も入力内容に近い断片を拾っているが、要約文としては未完成。 |

解釈:

test_003 では、LoRA Proposed が最も「入力の論点らしさ」を拾っている。特に「現金配るんですか」は参照要約の現金給付報道と対応する。ただし、出力は質問断片であり、要約に必要な「誰が何を主張し、首相がどう答えたか」という構造にはなっていない。

## Baseline と Proposed の違い

Proposed は `act` / `stance` ラベルを入力に含むため、モデルが発話構造を使える可能性がある。一方、今回のデータ量では、そのラベル形式自体を出力にコピーしてしまう例が出た。

特に Full FT + Proposed の test_003 では、`[委員長] act: question | stance: negative | text:` がそのまま生成されている。これは、モデルが「ラベルを手がかりに要約する」のではなく、「入力フォーマットを模倣する」方向に寄っていることを示す。

LoRA Proposed ではラベル漏れは弱まり、test_003 で質問内容の断片を拾えた。ただし、test_001 と test_002 では短すぎる出力になり、要約として必要な情報を落としている。

## Full FT と LoRA の違い

LoRA は full fine-tuning よりも保存サイズが小さく、今回の Baseline 条件では ROUGE-L も高かった。ただし、生成品質を見ると、LoRA Baseline も反復問題を解決できていない。

違いを要約すると次の通り。

- Full FT は定型句の反復に崩れやすい。
- Full Proposed はラベル形式のコピーが起きる。
- LoRA Baseline は人物名や政治文脈の語を拾う場合があるが、反復が強い。
- LoRA Proposed は入力中の質問断片を拾う場合があるが、短すぎる出力になりやすい。

## 指標と実際の品質のずれ

LoRA Baseline は 4 条件中で最も高い char ROUGE-L を出したが、実際の生成は反復が多い。これは、文字単位 ROUGE-L が日本語の断片的な一致や汎用表現の一致を拾いやすく、要約の事実性や構成を十分に評価できないためである。

そのため、今後は char ROUGE-L だけでなく、次の観点でも評価する必要がある。

- 主要人物を正しく含むか
- 主要論点を正しく含むか
- 質問と答弁の関係が表現されているか
- 入力ラベルが出力に漏れていないか
- 同一フレーズ反復がないか

## 改善方針

生成品質の改善には、学習方式よりも先にデータと生成設定の改善が必要である。

優先度が高い改善:

- 文字起こしから「ご視聴ありがとうございました」などの混入文を除去する
- 同一語句の長い反復を前処理で除去する
- Proposed 入力のラベルを `act=question stance=negative` のように短くし、出力にコピーされにくい形式に変える
- 要約ターゲットを増やし、最低でも数百件規模にする
- `no_repeat_ngram_size`、`repetition_penalty`、`length_penalty` を生成時に設定する
- `<extra_id_0>` を出さないよう、生成後処理または tokenizer 設定を調整する

暫定的には、次の実験では LoRA Baseline を主軸にしつつ、Proposed はラベル形式をより短くしたバージョンで再比較するのがよい。
