# retrieva-jp/t5-base-long LoRA 要約実験

実行日: 2026-06-07

## 目的

`google/mt5-small` では生成がほぼ崩壊していたため、より日本語に強い事前学習済みモデルとして `retrieva-jp/t5-base-long` を使い、LoRA fine-tuning を試した。

比較条件はこれまでと同じである。

- Baseline: 文字起こしのみを入力
- Proposed: 発話ごとに `act` / `stance` ラベルを付与した文字起こしを入力

## 実行条件

```bash
python data/prog/finetune_mt5_summarizer.py \
  --condition baseline \
  --tuning-mode lora \
  --model-id retrieva-jp/t5-base-long \
  --output-root runs/retrieva-t5-base-long \
  --learning-rate 1e-3 \
  --no-repeat-ngram-size 3 \
  --repetition-penalty 1.2
```

```bash
python data/prog/finetune_mt5_summarizer.py \
  --condition proposed \
  --tuning-mode lora \
  --model-id retrieva-jp/t5-base-long \
  --output-root runs/retrieva-t5-base-long \
  --local-files-only \
  --learning-rate 1e-3 \
  --no-repeat-ngram-size 3 \
  --repetition-penalty 1.2
```

LoRA 設定:

- `r=8`
- `alpha=16`
- `dropout=0.05`
- target modules: `q`, `v`
- trainable parameters: 884,736
- trainable ratio: 0.3561%
- adapter 保存サイズ: 各条件 約 34MB

生成設定:

- `num_beams=4`
- `generation_max_length=256`
- `no_repeat_ngram_size=3`
- `repetition_penalty=1.2`
- `<extra_id_*>` は後処理で削除

## 数値結果

| モデル | 学習方式 | 入力条件 | test loss | char ROUGE-L |
| --- | --- | --- | ---: | ---: |
| google/mt5-small | LoRA | Baseline | 10.7541 | 0.1043 |
| google/mt5-small | LoRA | Proposed | 8.6775 | 0.0577 |
| retrieva-jp/t5-base-long | LoRA | Baseline | 5.3284 | 0.1412 |
| retrieva-jp/t5-base-long | LoRA | Proposed | 5.3585 | 0.1334 |

`retrieva-jp/t5-base-long` は Baseline / Proposed の両方で `google/mt5-small` LoRA を上回った。特に Proposed は 0.0577 から 0.1334 に改善した。

## 暫定結論

`retrieva-jp/t5-base-long` に切り替えたことで、mT5-small より明確に改善した。

改善した点:

- `<extra_id_0>` が出なくなった。
- 「非核三原則」「山添拓」「玉木雄一郎」「財源」など、主題に近い語が出るようになった。
- char ROUGE-L は Baseline / Proposed とも mT5-small LoRA を上回った。

残る問題:

- 「総理」「でございます」「であります」の反復がまだ強い。
- Proposed はラベル漏れが残る。
- 要約というより、質疑断片の再構成に近い。
- データ数が少なく、論点を整理してニュース要約風に書くところまでは学習できていない。

次は、`retrieva-jp/t5-base-long` を使い続けつつ、次の改善を入れるのがよい。

- Proposed 入力から `[Speaker] act: ... | stance: ... | text:` の冗長な形式をやめる
- `ACT=question STANCE=negative 本文...` のように短いタグへ変換する
- 文字起こしの反復・ノイズ除去を先に行う
- 1 本の長い質疑をチャンクに分けて、中間要約から最終要約を作る
- `no_repeat_ngram_size` を 4 または 5 に上げる追加実験を行う
